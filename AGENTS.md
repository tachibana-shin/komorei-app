# AGENTS.md — Komorei

Android anime streaming app,~~Vietnamese UI~~ (multi location). Single `:app` module, package `git.shin.komorei`.
Stack: Compose + Hilt + Room + Media3 (ExoPlayer) + OkHttp/Moshi. No CI, no lint gate.

## Commands
- Fast compile: `./gradlew :app:compileDebugKotlin` (runs KSP — Hilt/Room/Moshi codegen errors surface here)
- Unit tests (JVM, Robolectric + Roborazzi): `./gradlew :app:testDebugUnitTest`
- Single test: `./gradlew :app:testDebugUnitTest --tests "git.shin.komorei.AnimeRepositoryTest"`
- **SDK runner (JVM vs real `.krx`)**: `./gradlew :app:testDebugUnitTest --tests "git.shin.komorei.sdk.*"` — `KrxRunnerIntegrationTest` loads the actual runner (JNA uniffi bindings + linux cdylib + real Kotlin host) via `uniffi.component.komorei_runner.libraryOverride` (injected by `testOptions.unitTests.all` in `app/build.gradle.kts`, pointing at `runner/target/debug/libkomorei_runner.so`); rebuild the lib with `cargo build -p komorei-runner` inside `runner/`. Android `.so`s (jniLibs, 3 ABIs) rebuild with `cargo ndk -t arm64-v8a -t armeabi-v7a -t x86_64 -o app/src/main/jniLibs build -p komorei-runner --release` (run inside `runner/`; set `ANDROID_NDK_HOME` to `/home/shin/android-sdk/ndk/<ver>`). **Layout**: the Rust runner crate is OWNED by this app repo (top-level `runner/`, self-contained workspace); `komorei-sdk/` stays a separate git repo beside it and is reached by RELATIVE PATH (`komorei = path = "../komorei-sdk/crates/lib"` in `runner/Cargo.toml`; `runner/tests/host.rs` loads its `.krx` fixture from `../komorei-sdk/examples/example-source/package.krx`). `runner/target` is a symlink to `/mnt/komorei-data/komorei-builds/runner-target` — the root partition is habitually full, so cargo targets are offloaded to `/mnt/komorei-data` (the sdk does the same: `komorei-sdk/target → /mnt/komorei-data/komorei-builds/komorei-sdk-target`). NEVER delete these symlinks or new builds refill `/`.
- **Uniffi Kotlin bindings are generated at BUILD TIME** — no committed file, no manual steps (flutter_rust_bridge style). Three chained Gradle tasks: `cargoBuildUniffi` (`cargo build` debug host cdylib in `runner/`) → `generateUniffiBindings` (`uniffi-bindgen generate --library target/debug/libkomorei_runner.so --language kotlin --no-format --out-dir ../app/build/generated/uniffi/kotlin`; CLI `uniffi-bindgen` 0.32.1 at `~/.cargo/bin`, override with `-PuniffiBindgen=/path`) → `patchUniffiBindings` (re-applies the `RunnerException.Source` patch — uniffi 0.32.1 Kotlin codegen emits a REDECLARING computed `override val message`; keep the constructor field `override val message`, delete the getter). The generated dir is wired into every variant via AGP 9's Variant API (`androidComponents.onVariants` → `sources.kotlin.addGeneratedSourceDirectory(patchUniffiBindings)`) so compile*Kotlin/KSP depend on it automatically — do NOT add it via SourceSet `srcDir` (error-deprecated). The file lands at `app/build/generated/uniffi/kotlin/git/shin/komorei/sdk/runner/komorei_runner.kt` (gitignored via `build`); `runner/uniffi.toml` sets `[bindings.kotlin] package_name = "git.shin.komorei.sdk.runner"` so NO sed is needed. Note: `Project.exec`/`javaexec` are REMOVED in Gradle 9.6+ — use Exec tasks, not `project.exec {}` in `doLast`. Adding a method to `KomoreiHost` = just change the trait, rebuild; the two `check(...)`s in the patch task fail loudly if uniffi codegen drifts.
- **SDK js module is REAL, WebView-backed** (`imports/js.rs` + `KrxHostImpl`): JS contexts are hidden JS-enabled WebViews, `webview_*` are full browser WebViews, eval results are opaque rid handles stored Kotlin-side. `KrxHostImpl` hops JS calls to the main looper (CountDownLatch, async `evaluateJavascript` awaited on the *runner* thread, never inside the main block), tracks page-load with a per-navigation latch (60s timeout, armed by loadUrl/loadHtml, released by `onPageFinished`), and reads/writes cookies via `CookieManager` (`getCookies` parses the header of the webview's `lastUrl`; `deleteCookie` sets an expired cookie, domain normalized to `https://`). `canvas` remains the ONLY stub (returns -1). Robolectric's paused looper can't deliver eval callbacks, so `KrxHostImpl.jsEvalOverride` (internal seam) supplies canned WebView-style JSON results; `KrxHostJsTest.kt` covers contexts/values/webviews/cookies/rules via that seam + ShadowWebView. Note: Robolectric's shadow CookieManager IGNORES expiry attributes (delete best verified on device); `loadDataWithBaseURL` is asserted via `ShadowWebView.lastLoadDataWithBaseURL`.
- **Runner calls run on a 32 MiB stack worker**: wasmi's interpreter recurses natively per wasm call, and the Android RELEASE-built executor's frames are large (debug/JVM frames are tiny — a 512 KiB JVM thread handles everything, but the 1 MiB Android instrumentation/app thread SIGSEGVs inside the executor: "Cause: stack pointer is close to top of stack" tombstone on `filters`/`home`). `KomoreiRunner::with_engine` therefore executes every call on a short-lived `std::thread::scope` + `Builder::spawn_scoped` worker with `stack_size(32 MiB)` (per-call spawn, mutex still serializes; `T: Send` bound on the closure result). Keep it — removing it regresses any source whose wasm call chain passes ~300 levels on device.

## Architecture
- Entry: `MainActivity` + `KomoreiApplication` (Hilt). `KomoreiApplication` exposes an `@Inject dataSourceFactory: KomoreiDataSourceFactory` — composables reach it via `(context.applicationContext as KomoreiApplication)`.
- `di/RepositoryModule`: shared OkHttpClient (User-Agent header, HttpLogging HEADERS, `WebViewCookieJar`, followRedirects) + ImageLoader + Room DB. Cookies from WebView flow into every media request automatically.
- **ALL data is fake** (commit "fake data"): `AnimeRepository` is mocked, `delay()` simulates the network. `getStream` returns real sample URLs (Mux HLS + public sample MP4s) so playback actually works. Retrofit is an unused dependency — scaffold for real sources. OkHttp/Moshi are used for real (Moshi via codegen for Room converters in `KomoreiTypeConverters`).
- **Sources tab ("Nguồn")** — an Aidoku Browse-tab port (`ui/screens/sources/`): `SourcesScreen` (searchable sections **Updates / Pinned / Installed**, long-press ⋮ menu: enable/disable, pin/unpin, uninstall) + `AddSourceSheet` (import `.aix`/`.krx` via SAF, per-repo external source list with "Cài" buttons) + `SourceReposScreen` (add/remove repo URLs). State: `SourcesViewModel` (search, actions, repos fetch states, one-shot Toast messages); persistence in `SourceStateStore` (**SharedPreferences**, Aidoku-style UserDefaults: disabled set, ordered pins, repo URLs, each mirrored to a StateFlow); repos fetched by `SourceReposRepository` (OkHttp + org.json — object `{sources:[...]}` or bare-array manifest, `file` = package URL; also `downloadPackage` for installs). **Every blocking OkHttp `.execute()` in `SourceReposRepository` is wrapped in `withContext(Dispatchers.IO)`** — the VM launches repo fetches in `viewModelScope` (Main), and without the IO hop the connect/read blocks the UI thread (the sheet froze at "Đang tải…" until this was fixed). The sheet auto-fetches all repos on open (`LaunchedEffect(repos) { refreshAllRepos() }`) so collapsed rows show Loaded/Unavailable (never a stale "Đang tải…"), and its Column is `verticalScroll`-enabled or "Thêm kho"/"Quản lý kho" get clipped off-screen. Bundled `.krx` sources cannot be uninstalled; imported ones persist in `filesDir/sources/`.
- **`KrxSourceRegistry` also loads user-installed `.krx`** from `filesDir/sources/` at startup (same `source.json` discovery as assets). `installKrx(bytes)` validates key pattern (`[A-Za-z0-9.\-]+`, not reserved), persists the file, registers metadata, loads the runner (rolls back on wasm failure); `uninstall(id)` deletes the file + drops runner/dispatcher (bundled = guarded by `isUserInstalled`). `sourceAppFlow` (StateFlow of app-model `Source`s) feeds `AnimeRepository.sourcesFlow`, which prepends the `all` aggregator and powers the **reactive** `HomeViewModel.sources` — a `StateFlow` combining `sourcesFlow` × `stateStore.disabled` (aggregator never filterable), collected by `HomeScreen`; disabling a source removes its tab live. `Source` carries `languages`/`contentRating` from the krx manifest (18+ badge in the sources list).
- **Anime "Lite" vs "full"**: list APIs return Lite; you MUST call `getAnimeUpdate(anime, needsDetails, needsChapters)` before `getStreamList`/`getStream`. `needsChapters=true` fetches episodes only for the current animeId/season (does not pull sibling seasons).
- **Player flow**: `PlayerViewModel` owns the single `ExoPlayer` engine and `PlayerPlaybackState` mirrors it (via `Player.Listener` + a 250ms position poller) — VM is the single source of truth (player, fullAnime, streams, selectedStreamId, streamData, segment interceptors). `AnimeDetailView` is a pass-through view. Flow: `openAnime`/`selectEpisode` → `loadStreams` (getAnimeUpdate needsDetails=true → getStreamList → getStream first server) → `buildMediaSource` on the shared engine. `loadStreams` is thin: it upgrades Lite→full then delegates the resolve/build tail to **`finishLoadStreams(full, episode, restorePosition)`**, which is also reused by the process-death restore (see below) so session restore rides the exact same pipeline.
- **Back navigation (player)**: `VideoPlayerSheet` composes a `BackHandler` that walks the player's OWN stack and must never let system back exit the activity while the player is up: active side menu → exit fullscreen → `EXPANDED` collapses to the mini player → `COLLAPSED` dismisses (`dismissPlayer`). Only once the sheet is `HIDDEN` (handler leaves composition) does back reach the NavHost (pop tab / app exit) — that's why back on the play screen "kills the app" symptom is fixed.
- **Process-death restore (savedState)**: `PlayerViewModel` injects `SavedStateHandle` (activity-scoped `hiltViewModel()` supplies it via the SavedStateRegistry) and mirrors the open session into keys `player_anime_id` / `player_episode_id` / `player_sheet_value` (private companion consts) — written on `openAnime`/`selectEpisode`/`setPlayerSheetValue`, cleared on `dismissPlayer`. `init` calls `restoreSession()`: read anime id → pick the Lite card from `allAnimes` → re-upgrade via `getAnimeUpdate(needsDetails=true, needsChapters=true)` to locate the same episode (Lite episodes are stubs, so the FULL list is required) → re-apply saved `sheetValue` (expanded / collapsed-mini) → `finishLoadStreams(full, episode, restorePosition = true)`. The playhead resumes from Room watch history via `restoreWatchTime` (the ≥3s/≥10s policy already wrote it) once the fresh source reports READY. **`isFullscreen` deliberately NOT restored** (avoids forcing landscape on cold start); a stale/unknown session (cleared keys, removed anime) silently opens the app fresh. Nav tabs themselves survive recreation via `rememberNavController()`'s saveable back stack; everything else (Home/Search/Library list scroll + search query state) is in-memory and resets on process death.
- **Watch history / auto-resume**: written via `LibraryRepository.saveProgress` — `PlayerViewModel.saveWatchTime()` autosaves from the poller only after ≥3s of playback has advanced into the episode (first save), then at most every ≥10s (all periodic saves reset `lastSaveUptimeMs = SystemClock.uptimeMillis()` on every save, periodic or boundary, so the spacing always holds between consecutive writes); STATE_ENDED saves immediately regardless of the 10s gap, as do the other boundaries (pause, openAnime/selectEpisode switch, dismiss). Resume uses `LibraryRepository.getWatchTime(...)` (a **suspend** seam — later a remote watch history can plug in without changing call sites), scheduled after `buildMediaSource` in `loadStreams`/`selectStream` (not on `retryStreams` refresh) and **applied as a `seekTo` only when the engine reports `STATE_READY`** — seeking right after `prepare()` is unreliable (the period is created asynchronously with the default position 0 and the seek can be silently dropped). Episodes ≥95% watched restart from 0. `dismissPlayer()` fully releases the engine (`stop()` + `clearMediaItems()`) and resets the whole `PlayerPlaybackState` (anime/episode/tracks/ranges/position) so reopening starts clean — a bare `pause()` left the stale source prepared (frozen frame + leftover state).
- **Key migration (MigrationHandler)**: "Di trú dữ liệu nguồn" in `SourceSettingsScreen` (confirm dialog) → `SourceMigrationRepository` (injects `AnimeDao` + `AnimeRepository`) re-keys every stored item of a source — distinct anime ids from `anime_library` + `watch_history` — through the runner's `migrateAnime`/`migrateEpisode` (`AnimeRepository.migrateAnime/migrateEpisode` → `registry.call`), then applies the plan in ONE `animeDao.applyLibraryMigration` transaction (delete stale rows, re-insert migrated with REPLACE — two old keys mapping onto one new merge, the re-insert wins). Remapper lambdas are `internal var` seams so the rewrite logic is testable without wasm; a null result (source won't load) is treated as identity so a half-loaded source can't corrupt the library. The UI surfaces a one-shot toast "Đã di trú X anime, Y tập (kiểm tra …)". Test: `SourceMigrationRepositoryTest` (in-memory Room + real fake-krx round-trip).
- **Player UI**: `VideoPlayerSheet` renders the engine inside `PlayerVideoArea` → media3 **`media3-ui-compose-material3`** `Player()` composable (official Compose UI, same 1.11.0 version) with custom top/center/bottom slots in the app's dark theme. Gestures (`PlayerGestures.kt`, ported from the official media3 demo `demos/compose/.../layout/modifiers.kt` — Apache-2.0): single-tap toggles controls, double-tap seeks ±10s (left/right half), hold-right-half fast-forwards 2x (VM remembers/restores base speed), vertical swipe left = window brightness / right = `player.volume`; thin AnimeRed progress line stays at the bottom edge when controls autohide (3.5s). In-player slide-in side menus (`PlayerSideMenu.kt`, like the anime-vsub reference): playlist icon opens the episode/season picker (`EpisodesContent` — shared with the detail `EpisodesBottomSheet`), Dns icon opens the server picker (`ServerMenuContent`), and a SkipNext button jumps to the next episode of the current season/chunk (hidden at the last one). Fake HUDs are gone — Refresh re-resolves the stream, Settings opens a playback-speed menu, Fullscreen drives `PlayerPlaybackState.isFullscreen` + immersive system bars. Swiping the sheet down collapses it into a YouTube-style floating mini player (`FloatingMiniPlayer`): the sheet's vertical position is a single `Animatable(sheetOffset)` (px) held by `VideoPlayerSheet` — a drag `snapTo`s it 1:1 to the finger (raw deltas, never an animated value fed back into the accumulator — that compounded lag and the sheet crept), and on release it springs toward the target while KEEPING the finger's release velocity (`animateTo(..., spring(dampingRatio = CRITICAL /*1.0 — no overshoot*/), initialVelocity = v)` — momentum; the old `animateFloatAsState` restarted the spring from rest on every release = the visible "khựng"; a slightly-underdamped 0.9 bounced past fullHeight, pushed `fraction` back over the bubble gate and ping-ponged the shared surface sheet↔bubble = black flicker). The collapse is a SLIDE + FADE — the WHOLE sheet Box follows the finger 1:1 via its own `Modifier.offset { IntOffset(0, sheetOffset) }` (a plain LAYOUT offset, NOT `graphicsLayer` — any layered ancestor of the TextureView renders BLACK, a bug that shipped once: "player area just black + black flickering popup"), and as it slides a black veil overlaying the column (`Color.Black.copy(alpha = collapse)`, a plain opaque overlay — it MUST be a sibling Box overlay, NOT a Column child, else a `fillMaxSize` child inside the Column starves the weighted detail to 0px) dims video + detail + controls progressively so the player "fade mờ ẩn hẳn". Only when the sheet is essentially FULLY off-screen (`collapse >= 0.98f`) does the mini bubble OPEN, with its OWN enter animation — scale-in pivoted at the corner it lands in (`TransformOrigin` from `miniBubblePos`) + a short fade = "mở mini player bằng animate"; there is deliberately NO continuous morph — the player must be fully hidden BEFORE the mini opens. The draggable is disabled at `COLLAPSED` so the app behind the bubble stays interactive (the overlay must not swallow touches). The bubble BUILDS IN at the corner it will occupy (no glide from the exit point) — the handoff is gated on `collapse >= 0.98f`. The bubble itself is a BIGGER 16:9 `clip(RoundedCornerShape(14.dp))` rendering the LIVE video surface (same TextureView `ComposePlayer`), tap-to-expand, minimal controls ONLY: play/pause top-left + close top-right (translucent circles), NO progress bar; it's free-dragged like a chat bubble and releasing it springs (`Animatable<Offset>` + `Offset.VectorConverter`) to the NEAREST of the 4 screen corners. Bubble size + corner anchors come from one shared `MiniPlayerGeometry.kt` (`computeMiniPlayerGeometry(maxW, maxH, density, bottomInsetPx)` — the bottom corners are raised above the app's bottom nav bar so the mini never covers it, wired from `MainScreen`'s Scaffold padding), controls are deliberately SMALL (32dp translucent circles w/ 8dp margins, ~17dp icons), and the bubble's top-left is HOISTED (`initialPosition`/`onPositionChange` → `miniBubblePos` in the sheet) so it keeps whatever corner the user snapped it to across collapse/expand cycles. The bubble is gated on `sheetValue == COLLAPSED && collapse >= 0.98f` so the shared engine never paints to two ComposePlayer surfaces, and it MUST be a **sibling of the sheet Box inside the `BoxWithConstraints`** (a child of the sheet would inherit the `.offset` translation and get carried off-screen when collapsed — the "tắt luôn player / không thấy mini player" bug).
- **Media3**: media source = `DefaultMediaSourceFactory(KomoreiDataSourceFactory)` (auto-detects HLS vs MP4). `KomoreiDataSourceFactory.configure(streamData, urlInterceptor?, dataInterceptor?)` injects `streamData.headers` into every sub-request and wraps with `TransformableHttpDataSource` when an interceptor is present.
- **Segment transformer**: `AnimeRepository.segmentUrlInterceptor`/`segmentDataInterceptor` are open/null — a real source just overrides these two properties and gets wrapped automatically.
- `StreamData.isContent == false` → treated as not playable (shows loading/error), no media source built.
- Model: `Episode` plays the role of "chapter" (kept the Episode name). `Episode.episodeNumber` is a **String**.
- Every displayed string is a string resource in `res/values/strings.xml` — never hardcode.
- **Loading UIs are shimmer skeletons, never circular spinners — EXCEPT inside the player** (the two `CircularProgressIndicator` usages in `PlayerVideoArea`/`PlayerSheets` are the ONLY allowed ones; that's the "playing/buffering" affordance on a media surface). Every other loading state uses the shimmer toolkit in `ui/components/Shimmer.kt` (`shimmerEffect` modifier + `AnimeCardSkeleton`/`SectionSkeleton`/`BannerCarouselSkeleton`/`ListingGridSkeleton`/`SearchResultSkeleton`/`ShimmerLoadingRow`). Full-page loading = a skeleton grid/rows shaped like the real content; inline "load more" = `ShimmerLoadingRow`. Don't add `CircularProgressIndicator` outside the player.
- Chips that need a min touch target: use plain `Modifier.clip` + `background` + `clickable` (see `ListingChipsRow`), NOT `Surface(onClick=...)`, whose `minimumInteractiveComponentSize()` floor pins the height to 48dp regardless of padding. Also always set an explicit `lineHeight` on small `Text` — otherwise the inherited `bodyLarge` `lineHeight = 24.sp` keeps the box tall no matter how small `fontSize` gets.

## Gotchas
- **Player surface MUST be a TextureView** (`PlayerVideoArea` passes `surfaceType = SURFACE_TYPE_TEXTURE_VIEW` to media3's `Player()`): the player lives in a draggable sheet — the WHOLE sheet Box moves via its own `Modifier.offset { IntOffset(0, sheetOffset) }` (layout placement) and it's re-laid-out on fullscreen, and a `SurfaceView` composites in its own window layer that ignores Compose offset/clip/scale — it punches an opaque black rectangle over the whole app (black screen outside the video, nothing visible in fullscreen, loading spinner/controls occluded). **Hard rule: NEVER put the TextureView (or any of its ancestor boxes: sheet box, video box, bubble) inside a `graphicsLayer` with alpha/scale/translation — the video renders BLACK** (that's the "player area just black + black flickering popup" bug from the round that tried a YouTube shrink-morph). `clip`/`shadow`/layout-`offset` are fine (the bubble uses corner clip + shadow and renders the live video; its enter animation lives on the AnimatedVisibility/parent and its drag/snap use a layout `offset` — never a surface ancestor). TextureView renders through the normal hierarchy and tracks the sheet. Same rule in the collapsed `FloatingMiniPlayer` bubble, which also renders the engine via `ComposePlayer` + `SURFACE_TYPE_TEXTURE_VIEW`.
- **Do NOT nest vertical scrollables**: `LazyVerticalGrid` inside an `item {}` of a `LazyColumn` → FATAL "measured with infinity maximum height" (usually triggered by prefetch). The "Related" section of the detail page deliberately uses a non-lazy grid (chunked rows) — keep it that way; any other nested grid must have a bounded height.
- **Player side menus must be OUTSIDE the sheet's Column**: in `VideoPlayerSheet`, the episode/server slide-in `PlayerSideMenu`s live in a sibling `Box` that overlays the whole sheet — NEVER as `Column` children. Their roots are `fillMaxSize()`, so inside the Column they each consume the full Column height and starve every `weight(1f)` child (the detail view, and the video box in fullscreen) down to 0 px — that was the "black below the player" / "everything disappears in fullscreen, progress bar squeezed to the top" bug. Same rule applies anywhere: a `fillMaxSize()` child inside a Column must carry `weight(...)`.
- "Unused" dependencies are **kept as comments** in `app/build.gradle.kts` + `gradle/libs.versions.toml` (datastore-preferences, Firebase, camera, play-services, ...) — don't remove them; uncomment to re-enable.
- `.env`/`.env.example` provide `API_KEY` via the Secrets Gradle Plugin (BuildConfig) for a future Gemini feature — currently just a placeholder, nothing reads it yet.
- Release builds need signing: env `KEYSTORE_PATH`/`STORE_PASSWORD`/`KEY_PASSWORD` or a root `my-upload-key.jks`. Debug needs nothing.
- Configuration cache is on (`gradle.properties`); changing build scripts may trigger a config cache rebuild.
- Versions: AGP 9.3.2, Kotlin 2.4.20, Compose BOM 2026.09.00, media3 1.11.0, Hilt 2.60.1; minSdk 24, targetSdk 36, compileSdk 37.
- **Never `remove(...)` from a jsoup `Elements`, even a copy** (`KrxHostImpl.htmlSiblings`): jsoup's `Elements` overrides `remove(int)` to also call `element.remove()`, which **detaches the element from the source tree** — the whole DOM silently corrupts (sibling/next/parent queries start returning null). `KrxHostImpl.htmlSiblings` builds the sibling list with `parent.children().filterNot { it === node }` (identity filter) instead. Note jsoup's `Element.equals` is content-based, so identity comparison is also the *correct* semantics (never remove a content-equal doppelgänger). Plain `MutableList`/`ArrayList` removal is safe — only `Elements` is dangerous.
- **Don't assume trait methods are the wasm export names — check `macros/mod.rs` `(@single …)` first**: most traits export one function per method (e.g. `DeepLinkHandler.handle_deep_link` → export `handle_deep_link`), but `MigrationHandler` is a **single gộp export `handle_key_migration(key_kind: 0|1, anime_key, episode_key)`** — there is NO `handle_anime_migration`/`handle_episode_migration` export. The runner API hides this: `KomoreiRunner.migrate_anime`/`migrate_episode` call `engine.call3("handle_key_migration", kind, desc…, …)` (kind passed as a RAW i32 descriptor, not an encoded pointer); calling the per-method names yields `RunnerException.ExportMissing`. New runner APIs for a trait must be written against the glue's actual exported names (add a runner-side test like `SourceMigrationRepositoryTest.runnerMapsAnimeKeyThroughWasm` to prove it).
- Tests: `app/src/test` runs on JVM with Robolectric (`isIncludeAndroidResources = true`); Roborazzi writes PNG screenshots to `src/test/screenshots/`.
