# AGENTS.md — Komorei

Android anime streaming app, ~~Vietnamese UI~~ (multi location). Single `:app` module, package `git.shin.komorei`.
Stack: Compose + Hilt + Room + Media3 (ExoPlayer) + OkHttp/Moshi. No CI, no lint gate.

## Commands
Note: if komorei-sdk folder not exists clone from https://github.com/tachibana-shin/komorei-sdk
- Fast compile: `./gradlew :app:compileDebugKotlin` (runs KSP — Hilt/Room/Moshi codegen errors surface here)
- **Unit tests (JVM, Robolectric + Roborazzi)**: `./gradlew :app:testDebugUnitTest` — runs the main task and then the runner-integration task (`testSdkRunnerUnitTest`, see the JNA/Robolectric note below), so one command covers everything. A single test is `./gradlew :app:testDebugUnitTest --tests "git.shin.komorei.AnimeRepositoryTest"`.
- **SDK runner only (JVM vs real `.krx`)**: `./gradlew :app:testSdkRunnerUnitTest` — `KrxRunnerIntegrationTest` loads the actual runner (JNA uniffi bindings + linux cdylib + real Kotlin host) via `uniffi.component.komorei_runner.libraryOverride` (injected by `testOptions.unitTests.all` in `app/build.gradle.kts`, pointing at `runner/target/debug/libkomorei_runner.so`); rebuild the lib with `cargo build -p komorei-runner` inside `runner/`. Android `.so`s (jniLibs, 3 ABIs) rebuild with `cargo ndk -t arm64-v8a -t armeabi-v7a -t x86_64 -o app/src/main/jniLibs build -p komorei-runner --release` (run inside `runner/`; set `ANDROID_NDK_HOME` to `/home/shin/android-sdk/ndk/<ver>`). **Layout**: the Rust runner crate is OWNED by this app repo (top-level `runner/`, self-contained workspace); `komorei-sdk/` stays a separate git repo beside it and is reached by RELATIVE PATH (`komorei = path = "../komorei-sdk/crates/lib"` in `runner/Cargo.toml`; `runner/tests/host.rs` loads its `.krx` fixture from `../komorei-sdk/examples/example-source/package.krx`). `runner/target` is a plain LOCAL directory (cargo writes artifacts to the root partition, which now has plenty of free space — no symlink/offload needed anymore; the old `/mnt/komorei-data` offload symlinks for `runner/target` and `komorei-sdk/target` were removed when the external drive died).
- **Uniffi Kotlin bindings are generated at BUILD TIME** — no committed file, no manual steps (flutter_rust_bridge style). Three chained Gradle tasks: `cargoBuildUniffi` (`cargo build` debug host cdylib in `runner/`) → `generateUniffiBindings` (`uniffi-bindgen generate --library target/debug/libkomorei_runner.so --language kotlin --no-format --out-dir ../app/build/generated/uniffi/kotlin`; CLI `uniffi-bindgen` 0.32.1 at `~/.cargo/bin`, override with `-PuniffiBindgen=/path`) → `patchUniffiBindings` (re-applies the `RunnerException.Source` patch — uniffi 0.32.1 Kotlin codegen emits a REDECLARING computed `override val message`; keep the constructor field `override val message`, delete the getter). The generated dir is wired into every variant via AGP 9's Variant API (`androidComponents.onVariants` → `sources.kotlin.addGeneratedSourceDirectory(patchUniffiBindings)`) so compile*Kotlin/KSP depend on it automatically — do NOT add it via SourceSet `srcDir` (error-deprecated). The file lands at `app/build/generated/uniffi/kotlin/git/shin/komorei/sdk/runner/komorei_runner.kt` (gitignored via `build`); `runner/uniffi.toml` sets `[bindings.kotlin] package_name = "git.shin.komorei.sdk.runner"` so NO sed is needed. Note: `Project.exec`/`javaexec` are REMOVED in Gradle 9.6+ — use Exec tasks, not `project.exec {}` in `doLast`. Adding a method to `KomoreiHost` = just change the trait, rebuild; the two `check(...)`s in the patch task fail loudly if uniffi codegen drifts.
- **Base64 & crypto are runner-NATIVE wasm imports** (`base64` / `crypto` linker-header modules, mirroring aidoku's `imports::base64`/`imports::crypto`): `base64::{encode(&[u8]) -> String, decode(&str) -> Option<Vec<u8>>}` (encode = standard-with-padding; decode tolerates standard padded/unpadded + URL-safe padded/unpadded), `crypto::{md5, sha1, sha256, hmac_sha1, hmac_sha256}` — all lowercase-hex `String`s, `hmac_sha*` takes `(data, key)`. Implemented with the Rust `base64`/`md-5`/`sha1`/`sha2`/`hmac` crates in `runner/src/imports/{base64,crypto}.rs` (wasmi) — pure CPU, **NO Kotlin host round trip** (unlike `std::current_date`); results return as a `store_raw` rid that wasm reads via `std::read_buffer` + `std::destroy` (negative rid = `None` for decode). The SDK wasm side (`komorei-sdk/crates/lib/src/imports/{base64,crypto}.rs`) declares the extern `base64`/`crypto` module functions; the SDK test host (`komorei-sdk/crates/test-runner/src/imports/`, wasmer) implements the SAME 7 functions so source `cargo test` works against them. Adding new linker entries is backward-compatible with old `.krx` (wasm imports only what it uses); a krx built against them needs the rebuilt runner cdylib + reinstalled `komorei-test-runner` (`cargo build -p komorei-test-runner` in `komorei-sdk/` → copy `target/debug/komorei-test-runner` to `~/.cargo/bin/`).
- **SDK js module is REAL, WebView-backed** (`imports/js.rs` + `KrxHostImpl`): JS contexts are hidden JS-enabled WebViews, `webview_*` are full browser WebViews, eval results are opaque rid handles stored Kotlin-side. `KrxHostImpl` hops JS calls to the main looper (CountDownLatch, async `evaluateJavascript` awaited on the *runner* thread, never inside the main block), tracks page-load with a per-navigation latch (60s timeout, armed by loadUrl/loadHtml, released by `onPageFinished`), and reads/writes cookies via `CookieManager` (`getCookies` parses the header of the webview's `lastUrl`; `deleteCookie` sets an expired cookie, domain normalized to `https://`). `canvas` remains the ONLY stub (returns -1). Robolectric's paused looper can't deliver eval callbacks, so `KrxHostImpl.jsEvalOverride` (internal seam) supplies canned WebView-style JSON results; `KrxHostJsTest.kt` covers contexts/values/webviews/cookies/rules via that seam + ShadowWebView. Note: Robolectric's shadow CookieManager IGNORES expiry attributes (delete best verified on device); `loadDataWithBaseURL` is asserted via `ShadowWebView.lastLoadDataWithBaseURL`.
- **Runner calls run on a 32 MiB stack worker**: wasmi's interpreter recurses natively per wasm call, and the Android RELEASE-built executor's frames are large (debug/JVM frames are tiny — a 512 KiB JVM thread handles everything, but the 1 MiB Android instrumentation/app thread SIGSEGVs inside the executor: "Cause: stack pointer is close to top of stack" tombstone on `filters`/`home`). `KomoreiRunner::with_engine` therefore executes every call on a short-lived `std::thread::scope` + `Builder::spawn_scoped` worker with `stack_size(32 MiB)` (per-call spawn, mutex still serializes; `T: Send` bound on the closure result). Keep it — removing it regresses any source whose wasm call chain passes ~300 levels on device.
- **Host callbacks must be `Result` (never a bare `T`), and the profiles use `panic = "unwind"`**: a wasm execution reaches the Kotlin app through the `KomoreiHost` foreign trait, and uniffi answers a host that breaks the FFI contract by PANICKING in `LiftReturn::handle_callback_unexpected_error`. That panic starts under an `extern "C"` callback frame, which Rust marks `nounwind`, so **it cannot be caught** — `catch_unwind` outside aborts with "panic in a function that cannot unwind", and under `panic = "abort"` it takes the whole host process down (an app crash on Android, a SIGABRT that silently dropped ~200 tests in the Gradle JVM). The fix is structural: every `KomoreiHost` method returns `Result<T, RunnerError>`, which selects uniffi's `LiftReturn for Result<R, E>` and converts the failure into `Err(RunnerError::HostCallback(..))` via `From<UnexpectedUniFFICallbackError> for RunnerError` — the import then reports its own "no usable value" code and the source carries on. `with_engine` additionally wraps the call in `catch_unwind` (inside the lock's scope, so the mutex is never poisoned) for panics that never cross a callback. **The Kotlin side needs no change**: uniffi maps `Result<T,E>` for a foreign trait to "return T, throw E", so `KrxHostImpl`'s signatures stay as they are. `runner/tests/host.rs` implements the trait in Rust and DOES need updating. Changing a signature means touching the `imports/*.rs` call sites too — `host_opt(..)` in `html.rs`/`js.rs` folds a failed call into the `None` arm the source already handles.
- **Tests that invoke the wasm runner run in their OWN JVM** (`testSdkRunnerUnitTest`, see `app/build.gradle.kts`): the uniffi bindings load the runner cdylib through JNA, and every `KomoreiHost` call re-enters the JVM through a JNA callback. JNA initialises its native side once per classloader while Robolectric hands every test class a fresh sandbox classloader, so running runner tests in the same JVM as the ~35 Compose/Robolectric classes leaves JNA's shared native callback state pointing at objects from discarded sandboxes. The symptom was an intermittent, load-dependent `host callback failed: not enough bytes remaining in buffer (0 < 1)` — the `RustBuffer` out-param came back empty and the host method never ran (no OkHttp, no SharedPreferences read), which failed `Nguonc…`/`Vsmov…`/`Ophim…`/`Nguonphim…` only when they followed the Compose classes. The dedicated task carries the `git.shin.komorei.sdk.*` classes plus the root-package suites that really invoke an export (`AnimeRepositoryTest`, `PlayerViewModelTest`, `RecommendedAnimeFallbackTest`, `SourceHomeScopedTest`); `testDebugUnitTest` excludes them and is `finalizedBy` the sdk task, so one command still runs everything. `NguonphimeLivePlaybackE2ETest` hits the LIVE site by design and skips itself via JUnit `Assume` when the host is unreachable; its NGC/PAI grant is per-IP/geo, so a site-side refusal there is tolerated and reported rather than failed (the same pipeline is asserted offline by `NguonphimeSourceRunnerIntegrationTest`).
- **Sources repo (standalone)**: the `sources/` collection is its OWN git repo beside the app (like `komorei-sdk/`, gitignored) — standard aidoku-community layout: every crate lives under `<root>/sources/<id>/` (`sources/sources/vi.ophim` = `vi.ophim`, `sources/sources/vi.kkphim` = `vi.kkphim`, `sources/sources/vi.nguonc` = `vi.nguonc`, `sources/sources/vi.nguonphim` = `vi.nguonphim` — those two share one nguonc-style REST engine, see `NguonphimSourceRunnerIntegrationTest`; `sources/sources/vi.nguonphime` = `vi.nguonphime` — an HTML scrape of the "Nguồn 360" box site nguonphime.site with the NP Checker bounce, PAI base64 grab playlists and the NGC streamc grant, see `NguonphimeSourceRunnerIntegrationTest`) plus the `.skip`-marked `sources/sources/vi.fake-source` dev fixture (bundled into the app assets instead). Build/publish it from inside `sources/` with the SDK CLI: `komorei repo build --root . --output public` (packages every non-skipped source → `public/sources/<id>-v<N>.krx` + `public/icons/<id>-v<N>.png` + `index.json`/`index.min.json`), `komorei repo verify --root .` (validates wasm exports, icon 128×128 opaque, source.json schema), `komorei repo serve --root .` (build + local HTTP for on-device testing), `komorei repo init` (scaffold a new repo). `discover_source_dirs` accepts the standard `<root>/sources/<id>` layout ONLY (a crate outside the `sources/` container is an error); a crate containing a `.skip` file is excluded from build/verify/serve and from CI lint. The app reads `index.min.json` and resolves the RELATIVE `downloadURL`/`iconURL` against the manifest URL (`SourceReposRepository.absolutizeUrl`). **Source icons are per-site** (each `sources/sources/*/res/icon.png` is a **128×128 opaque PNG**, enforced by `komorei repo verify`): `vi.kkphim` ships KKPhim's real gradient-`K` favicon (64×64, from `kkphim1.com/uploads/favicon-Kgmpf3nB.png`), `vi.nguonc` ships Nguồn C's real orange-TV `tv.png` (from `phim.nguonc.com/public/images/Logo/tv.png`), and `vi.nguonphim` ships the real Nguồn Phim red/white favicon (46×48, crawled by DuckDuckGo/Google for `nguonphim.net`) — all composited on a dark `#0E1116` base. `vi.ophim` (`OP` in `#FF2A55`) and `vi.nguonphime` (`N360` in `#A78BFA`) are monogram badges in Noto Sans Black: OPhim's mirrors are all dead/Cloudflare (no reachable logo), and `nguonphime.site`'s only favicon is the SAME borrowed generic file the `nguonphim.net` "NP Checker" family shares (identical 46×48 mark served for both domains — reusing it would make the two rows indistinguishable, so the violet N360 monogram deliberately stays). The `.skip`'d `vi.fake-source` keeps its own red/white dev mark (bundled krx, not repo build). Regenerating one = rebuild its SVG (`rsvg-convert -w 128 -h 128 in.svg -o out.png`; remember the `<image>` href must resolve relative to the SVG file) + a `repo build`. The JVM integration tests load `komorei.test.ophimKrx` → `sources/sources/vi.ophim/package.krx` and `komorei.test.nguonphimKrx`/`komorei.test.nguonphimeKrx` → the `vi.nguonphim`/`vi.nguonphime` packages.

## Architecture
- Entry: `MainActivity` + `KomoreiApplication` (Hilt). `KomoreiApplication` exposes an `@Inject dataSourceFactory: KomoreiDataSourceFactory` — composables reach it via `(context.applicationContext as KomoreiApplication)`.
- `di/RepositoryModule`: shared OkHttpClient (User-Agent header, HttpLogging HEADERS, `WebViewCookieJar`, followRedirects) + ImageLoader + Room DB. Cookies from WebView flow into every media request automatically.
- **JS-challenge bypass (403 → WebView)**: `KrxHostImpl.netRequest` treats a response as a challenge only when it is a 403..503 `text/html` body carrying `CHALLENGE_MARKERS` (`cf-challenge`, `Just a moment`, `Xác Minh An Toàn`, `captcha`, an empty `<title></title>`, ...) — a bare 403 is returned as-is (no WebView/dialog/retry). Solve order: (1) **headless** — `solveHeadlessOnce` loads the URL in a hidden JS WebView and polls `CHALLENGE_CHECK_JS` until the markers vanish (bounded by `CHALLENGE_*` constants; use `System.nanoTime()`, NOT `SystemClock.uptimeMillis()` — the latter is a *frozen shadow clock* under Robolectric and hangs the poll loop); (2) **visible fallback** — process-wide `JsChallengeCoordinator.requestUserBypass` publishes `pending` → `ChallengeBypassDialog` (mounted at the end of `MainScreen`), single-flight, resumed by `completeBypass`/`cancelBypass`. It then retries up to `MAX_403_RETRIES` with the fresh cookies (WebView → `CookieManager` → `WebViewCookieJar`). The solve MUST run on the runner thread — the old code awaited the page-load latch inside `onMainThread {}`, blocking the main looper so `onPageFinished`/`evaluateJavascript` never fired (every 403 froze the app). Every WebView neutralizes Android's autogenerated `X-Requested-With` fingerprint: `WEBVIEW_ANTI_FINGERPRINT_HEADERS` on `loadUrl` + `stripFingerprintHeaders` in `shouldInterceptRequest` (hardened `FingerprintFreeWebResourceRequest`, no `by` delegation). Test seams: `jsEvalOverride`, `onChallengeWebViewCreated`, `challengePollIntervalMs`/`challengeSolveTimeoutMs`/`challengeLoadTimeoutMs`; `KrxHostChallengeTest` + `ChallengeBypassDialogTest` cover it.
- **ALL data is fake** (commit "fake data"): `AnimeRepository` is mocked, `delay()` simulates the network. `getStream` returns real sample URLs (Mux HLS + public sample MP4s) so playback actually works. Retrofit is an unused dependency — scaffold for real sources. OkHttp/Moshi are used for real (Moshi via codegen for Room converters in `KomoreiTypeConverters`).
- **Sources tab** — an Aidoku Browse-tab port (`ui/screens/sources/`): `SourcesScreen` (searchable sections **Updates / Pinned / Installed**, long-press ⋮ menu: enable/disable, pin/unpin, uninstall) + `AddSourceSheet` (**Aidoku `AddSourceView`-style flat catalog**: import `.krx` via a **header icon** — Aidoku's IMPORT_SOURCE folded into the top bar next to the language filter, no big button; SAF picker with `"*/*"`. Every repo's sources merged into ONE deduped list via `buildExternalCatalog` in `ExternalCatalog.kt` — duplicate ids keep the newest advertised version (`compareVersions`), sorted by name — with a search pill, one-tap Get buttons, explicit empty states (no repos ("Thêm kho" CTA), repos down (retry), no matches), a **language filter button** in the header (Aidoku `AddSourceFilterMenu` — multi-select DropdownMenu of the catalog's distinct language tags, "Tất cả ngôn ngữ" clears, selected tags tint the icon AnimeRed; narrowing uses the pure `filterByLanguages` in `ExternalCatalog.kt`), and **installed sources are NEVER stripped from the list** — unlike `AddSourceView.filterExternalSources` they stay visible with a "Đã cài" check pill + `SourceReposScreen` (add/remove repo URLs). State: `SourcesViewModel` (search, actions, repos fetch states, one-shot Toast messages); persistence in `SourceStateStore` (**SharedPreferences**, Aidoku-style UserDefaults: disabled set, ordered pins, repo URLs, each mirrored to a StateFlow); repos fetched by `SourceReposRepository` (OkHttp + org.json — object `{sources:[...]}` or bare-array manifest, `file` = package URL; also `downloadPackage` for installs). **Every blocking OkHttp `.execute()` in `SourceReposRepository` is wrapped in `withContext(Dispatchers.IO)`** — the VM launches repo fetches in `viewModelScope` (Main), and without the IO hop the connect/read blocks the UI thread (the sheet froze at "Loading…" until this was fixed). The sheet auto-fetches all repos on open (`LaunchedEffect(repos) { refreshAllRepos() }`) so the catalog is already populated (never a stale "Đang tải…"), and its body is a `LazyColumn` inside a Column capped at ~92% of the screen height (`.heightIn`) — the wrap-content list room is pre-bounded so the LazyColumn's `weight(1f, fill = false)` never hits an unbounded-height measurement, and the whole thing behaves like an Aidoku pageSheet (short content = compact sheet, long catalog = scrollable near-fullscreen). Bundled `.krx` sources cannot be uninstalled; imported ones persist in `filesDir/sources/`.
- **CI / release / OTA** — `.github/workflows/android-ci.yml` checks out the separate public `komorei-sdk` and `komorei-sources` sibling repos, builds the Rust fixtures, runs `cargo test` for the runner, and runs the Gradle/JVM test + debug APK build on JDK 21. `.github/workflows/android-release.yml` calls that gate, uses Bun exclusively (`bun ci`, `bunx`, `bun run`; no npm), predicts a Conventional Commit release with semantic-release, updates `VERSION_NAME`/`VERSION_CODE` in `gradle.properties`, builds a signed APK/AAB, verifies their signatures, and publishes GitHub Release assets. The app’s `UpdateManager` is a direct-distribution updater: it checks the latest GitHub Release, requires a single APK with a GitHub SHA-256 digest, streams to app-private cache storage, verifies size/package/versionCode/signing certificate, then opens the Android installer from the user-initiated Settings → Cập nhật ứng dụng flow. This is intentionally not a Play In-App Update flow; the `REQUEST_INSTALL_PACKAGES` permission is only for the direct APK distribution channel.
- **Deep links** — Komorei deliberately registers **only `komorei://`** (no `aidoku://`, HTTPS, or universal-link filters). `MainActivity` submits content URIs to `DeepLinkManager` for source `handle_deep_link`; `ExternalDeepLinkParser` first claims `komorei://addSourceList?url=...` and `komorei://addSource?url=...`, and `ExternalDeepLinkHandler` validates/downloads through the same repo/registry paths as the Sources UI before showing a Toast. Nested target URLs may be HTTP(S), but the incoming URI itself must use `komorei://`.
- **App-shell tabs are DATA-DRIVEN** (`ui/navigation/MainTab.kt`): `mainTabs` is the single list of top-level destinations (Home / Sources / Search / Library / Settings) shared by BOTH `MainBottomNavigation` (phones) and `MainNavigationRail` (wide) in `ui/components/MainNavigationBars.kt` — adding a tab = add a `Screen` + one `MainTab` entry, never two hardcoded item blocks. The phone bar is a **FIXED, evenly-spaced `Row`** (each item `weight(1f)`, no horizontal scroll / no auto-scroll shifting) since exactly 5 destinations fit; the wide **rail** stays a scrollable `LazyColumn` that `LaunchedEffect` auto-scrolls the selected tab into view (a tab reached by deep link/back-stack is always visible). Tabs keep the `tab_<key>` / `rail_tab_<key>` testTags. **Screen tests inject ViewModels explicitly, never via `hiltViewModel()`** — `createComposeRule()`'s host is a plain `ComponentActivity`, not a Hilt component holder, so ANY `hiltViewModel()` evaluated at compose time throws `Given component holder … does not implement GeneratedComponent`. Every screen therefore takes `viewModel: X = hiltViewModel()` as a *parameter*, and `MainScreen` threads `playerViewModel` / `deepLinkViewModel` / `homeViewModel` down into `MainNavigationHost` so the START destination composes in a test host (the other routes resolve their own on first navigation and are covered by their own screen tests). The bars' own tab/selection behaviour is asserted directly in `MainNavigationBarsTest` (no VM graph), and the shell's two width branches in `MainScreenTest` (phone) / `MainScreenRailTest` (`MediumTablet`, >600dp) — the qualifier is a class-level Robolectric knob, hence the split. **Settings** (`ui/screens/settings/`) is the app-wide settings tab (distinct from per-source settings: repo manager entry, clear image cache/cookies/search history, app version). **Notifications** (`ui/screens/notifications/` + `data/NotificationStore.kt`, a `@Singleton` in-memory inbox that also mirrors source `handleNotification` semantics) is NOT a tab — it is opened from the bell button in the Home header (`home_notifications_button`), and because it is a sub-page it hides the bottom bar and carries its own back arrow (like SourceRepos).
- **Settings sub-pages** — `Settings → About` (`ui/screens/about/AboutScreen.kt`) mirrors Aidoku's `SettingsAboutView` with BuildConfig version/build and GitHub/Discord/Ko-fi links; `Settings → Insights` (`ui/screens/insights/`) mirrors Aidoku's `InsightsView` with streaks, a 365-day heatmap, stat tiles, and monthly bars. `InsightsData.from()` derives the values from `watch_history` (the Android equivalent of Aidoku reading sessions; hours are estimated from saved episode progress), while `InsightsViewModel` reads the table on `Dispatchers.IO`. Both routes hide the phone bottom bar and carry their own back arrow.
- **Backup / Google Drive** — `ui/screens/backup/BackupScreen.kt` ports Aidoku's `BackupsView` / `BackupCreateView` / restore-confirmation flow to a Komorei-specific, versioned JSON `.kbackup` format. `BackupRepository` snapshots Room (`anime_library`, `watch_history`, opt-in `krx_defaults`) plus source state/search history and optional user-installed `.krx` packages; null sections are left untouched on restore, and a safety snapshot is created before destructive restore. Drive uses `AuthorizationClient` with the `drive.appdata` scope and a dedicated no-cookie/no-header-logging OkHttp client against the hidden `appDataFolder`. Optional background sync is a unique WorkManager periodic job (`BackupSyncWorker`) with a persisted enable toggle and 6h/12h/daily/2d/weekly interval; it uploads only when the remote `modifiedTime` matches the last successful baseline, otherwise it reports `REMOTE_CHANGED` instead of overwriting another device. A worker can use Play services' cached authorization but cannot show consent UI, so it reports `AUTH_REQUIRED` when foreground reconnection is needed. OAuth IDs come from ignored `local.properties` (`google.drive.android.clientId`, `google.drive.web.clientId`) or `GOOGLE_ANDROID_CLIENT_ID` / `GOOGLE_WEB_CLIENT_ID`; downloaded `client_secret_*.json` / `google-services.json` files are ignored and must never be committed.
- **Android TV navigation is native Compose focus, not leanback** (`ui/tv/TvUi.kt`): the manifest installs on TVs too (optional `uses-feature` leanback/touchscreen + a `LEANBACK_LAUNCHER` intent-filter category). `MainActivity` provides `LocalTvMode` (detected once via `UiModeManager`; always `false` under Robolectric's phone config, so **every highlight below is an identity no-op on phones/tablets and in ALL tests**), and every interactive surface carries `Modifier.tvFocus(...)` — a scale-up (`graphicsLayer`) + animated accent ring (`border`) — on: `AnimeCard`, banner, nav rail/bottom items, source tabs, listing chips, filter pills (the whole `FilterPill` family), genre cards, `DetailPillButton`, `ServerOptionChip`, source rows/update/Get pills, settings rows, player controls (rewind/play/forward, subtitle/settings, fullscreen, skip pill) and player side-sheet rows (seasons, episode cards, servers, settings/selection items). **The pass is exhaustive** — every header icon, back/close button, `TextButton`/`Button`, `DropdownMenuItem` (material3 applies the item modifier OUTSIDE its internal `clickable`, so `tvFocus` tracks the menu item), dialog option row, see-all `SectionHeader` strip, metadata chip/genre link, the filter sheet's reset/close + the sort/select/multi-select/check `Filter*Group` chips, the uninstall/add-repo/browser-challenge dialogs, the mini player's tap-to-expand ring + play/close buttons, and the player's lock/retry/next-episode/playlist/server/quality/speed controls also carry it. Deliberate EXCEPTIONS: full-width rows use `scale = 1.0f` (ring only, no layout-shifting grow); scrollable side-menu BACKDROPS and the touch-sink panel do NOT get it (they'd be giant invisible D-pad targets — system BACK already dismisses them); text fields signal focus through `CompactInput`'s own AnimeRed border tint, so only their inner clear button is ringed. `tvFocus` MUST be placed on the SAME modifier chain as, and BEFORE/outside, the item's `clickable` so its `onFocusChanged` observes the node; it never intercepts input. Lazy rows/grids scroll focused items into view natively; Home's primary left/right source switching is the **SourceTabBar** (the pager is NOT a cross-page focus target — only composed pages are focus-reachable, so don't add `beyondViewportPageCount` expecting D-pad to jump source pages). `TvInitialFocus(focusRequester)` auto-focuses the Home source bar's first tab and the Discover search field on TV only (SourceSearch already auto-focuses its input on blank open for all devices). The TextureView rule still holds — `tvFocus`'s `graphicsLayer` is never placed on or above a player surface. D-pad focus MOVEMENT is only verifiable on-device (Robolectric's window never grants focus), so `TvUiTest` pins the no-op/click contracts instead.
- **Launcher icon = the Home-header brand lockup**: adaptive icon (`mipmap-anydpi-v26/ic_launcher{,_round}.xml`) = `ic_launcher_background` (dark gradient vector) + `ic_launcher_foreground` (layer-list, 66dp item → `drawable-nodpi/ic_launcher_logo.png`, a **1024×1024 transparent PNG**). The art reproduces the Home header logo exactly: the Material `local_fire_department` filled glyph in `AnimeRed` (`#FF2A55`) above the `"Komo"` (`TextPrimary` `#F8FAFC`) + `"rei"` (`AnimeRed`) wordmark (Noto Sans Black), all centered inside the 66dp safe circle (max content radius ~98% of the inscribed circle). Raster masters are SVG — `launcher-full.svg` (gradient background + lockup, for the legacy density PNGs in `mipmap-{m,h,x,xx,xxx}dpi/ic_launcher{,_round}.png` at 48/72/96/144/192 — these also fix the pre-26 launcher, which previously had NO density fallbacks) and `launcher-fg.svg` (transparent lockup for the adaptive foreground) — see `/tmp/opencode/` at generation time (not committed). Regenerating: `rsvg-convert -w 1024 -h 1024 launcher-fg.svg -o ic_launcher_logo.png` + rsvg per density into `mipmap-*`. - **Player flow**: `PlayerViewModel` owns the single `ExoPlayer` engine and `PlayerPlaybackState` mirrors it (via `Player.Listener` + a 250ms position poller) — VM is the single source of truth (player, fullAnime, streams, selectedStreamId, streamData, segment interceptors). `AnimeDetailView` is a pass-through view. Flow: `openAnime`/`selectEpisode` → `loadStreams` (getAnimeUpdate needsDetails=true → getStreamList → getStream first server) → `buildMediaSource` on the shared engine. `loadStreams` is thin: it upgrades Lite→full then delegates the resolve/build tail to **`finishLoadStreams(full, episode, restorePosition)`**, which is also reused by the process-death restore (see below) so session restore rides the exact same pipeline.
- **Back navigation (player)**: `VideoPlayerSheet` composes a `BackHandler` that walks the player's OWN stack and must never let system back exit the activity while the player is up: active side menu → exit fullscreen → `EXPANDED` collapses to the mini player → `COLLAPSED` dismisses (`dismissPlayer`). Only once the sheet is `HIDDEN` (handler leaves composition) does back reach the NavHost (pop tab / app exit) — that's why back on the play screen "kills the app" symptom is fixed.
- **Process-death restore (savedState)**: `PlayerViewModel` injects `SavedStateHandle` (activity-scoped `hiltViewModel()` supplies it via the SavedStateRegistry) and mirrors the open session into keys `player_anime_id` / `player_episode_id` / `player_sheet_value` (private companion consts) — written on `openAnime`/`selectEpisode`/`setPlayerSheetValue`, cleared on `dismissPlayer`. `init` calls `restoreSession()`: read anime id → pick the Lite card from `allAnimes` → re-upgrade via `getAnimeUpdate(needsDetails=true, needsChapters=true)` to locate the same episode (Lite episodes are stubs, so the FULL list is required) → re-apply saved `sheetValue` (expanded / collapsed-mini) → `finishLoadStreams(full, episode, restorePosition = true)`. The playhead resumes from Room watch history via `restoreWatchTime` (the ≥3s/≥10s policy already wrote it) once the fresh source reports READY. **`isFullscreen` deliberately NOT restored** (avoids forcing landscape on cold start); a stale/unknown session (cleared keys, removed anime) silently opens the app fresh. Nav tabs survive recreation via `rememberNavController()`'s saveable back stack, and every bottom-nav/rail tab click uses the canonical `popUpTo(startDestinationId) { saveState = true }; launchSingleTop = true; restoreState = true` pattern (phone + rail) — switching tabs pops the current tab's stack WITH its saved state instead of destroying it, so each tab (including pushed sub-pages like SourceHome/SourceSearch) is restored exactly when you come back. **Search state is the exception to "in-memory"**: `SearchViewModel` (Discover) and `SourceSearchViewModel` (per-source) both mirror their live params (query, genre/rating/language/sources; query + enabled `FilterValue`s) into the entry's `SavedStateHandle` on every change and re-read them in `init` BEFORE the debounced pipeline collects (`drop(1)` skips the pipeline's own initial emission — its debounce would read the default 300ms window even when a test set 0 after construction; the restored non-default search runs directly instead). Result: search query + filters survive tab switches AND process death (re-created NavBackStackEntry restores its `SavedStateHandle`). The per-source search ALSO carries its state in the URL — `Screen.SourceSearch` route is `source_search/{sourceId}?query={query}&filters={filters}` (percent-encoded, decoded by Navigation), `createRoute(sourceId, query, filters)` overload builds it, and `ui/navigation/SearchArgsCodec.kt` JSON-encodes the `List<FilterValue>` via Moshi + `FilterValueJsonAdapter` (register with `Moshi.Builder().add(FilterValue::class.java, …)`, NOT `.add(adapterInstance)` — that throws "Expected at least one @ToJson or @FromJson method"). The `${sourceId}`-arg keys are shadowed by VM-written handle values (regular map wins over args in `SavedStateHandle.get`), so a restored entry returns the LIVE search, not stale route args. Home/SourceHome/Library list scroll + grid positions remain in-memory (reset on process death).
- **Watch history / auto-resume**: written via `LibraryRepository.saveProgress` — `PlayerViewModel.saveWatchTime()` autosaves from the poller only after ≥3s of playback has advanced into the episode (first save), then at most every ≥10s (all periodic saves reset `lastSaveUptimeMs = SystemClock.uptimeMillis()` on every save, periodic or boundary, so the spacing always holds between consecutive writes); STATE_ENDED saves immediately regardless of the 10s gap, as do the other boundaries (pause, openAnime/selectEpisode switch, dismiss). Resume uses `LibraryRepository.getWatchTime(...)` (a **suspend** seam — later a remote watch history can plug in without changing call sites), scheduled after `buildMediaSource` in `loadStreams`/`selectStream` (not on `retryStreams` refresh) and **applied as a `seekTo` only when the engine reports `STATE_READY`** — seeking right after `prepare()` is unreliable (the period is created asynchronously with the default position 0 and the seek can be silently dropped). Episodes ≥95% watched restart from 0. `dismissPlayer()` fully releases the engine (`stop()` + `clearMediaItems()`) and resets the whole `PlayerPlaybackState` (anime/episode/tracks/ranges/position) so reopening starts clean — a bare `pause()` left the stale source prepared (frozen frame + leftover state).
- **Key migration (MigrationHandler)**: "Migrate source data" in `SourceSettingsScreen` (confirm dialog) → `SourceMigrationRepository` (injects `AnimeDao` + `AnimeRepository`) re-keys every stored item of a source — distinct anime ids from `anime_library` + `watch_history` — through the runner's `migrateAnime`/`migrateEpisode` (`AnimeRepository.migrateAnime/migrateEpisode` → `registry.call`), then applies the plan in ONE `animeDao.applyLibraryMigration` transaction (delete stale rows, re-insert migrated with REPLACE — two old keys mapping onto one new merge, the re-insert wins). Remapper lambdas are `internal var` seams so the rewrite logic is testable without wasm; a null result (source won't load) is treated as identity so a half-loaded source can't corrupt the library. The UI surfaces a one-shot toast "Migrated X anime, Y episodes (verify …)". Test: `SourceMigrationRepositoryTest` (in-memory Room + real fake-krx round-trip).
- **Player UI**: `VideoPlayerSheet` renders the engine inside `PlayerVideoArea` → media3 **`media3-ui-compose-material3`** `Player()` composable (official Compose UI, same 1.11.0 version) with custom top/center/bottom slots in the app's dark theme. Gestures (`PlayerGestures.kt`, ported from the official media3 demo `demos/compose/.../layout/modifiers.kt` — Apache-2.0): single-tap toggles controls, double-tap seeks ±10s (left/right half), hold-right-half fast-forwards 2x (VM remembers/restores base speed), vertical swipe left = window brightness / right = `player.volume`; thin AnimeRed progress line stays at the bottom edge when controls autohide (3.5s). In-player slide-in side menus (`PlayerSideMenu.kt`, like the anime-vsub reference): playlist icon opens the episode/season picker (`EpisodesContent` — shared with the detail `EpisodesBottomSheet`), Dns icon opens the server picker (`ServerMenuContent`), and a SkipNext button jumps to the next episode of the current season/chunk (hidden at the last one). Fake HUDs are gone — Refresh re-resolves the stream, Settings opens a playback-speed menu, Fullscreen drives `PlayerPlaybackState.isFullscreen` + immersive system bars. Swiping the sheet down collapses it into a YouTube-style floating mini player (`FloatingMiniPlayer`): the sheet's vertical position is a single `Animatable(sheetOffset)` (px) held by `VideoPlayerSheet` — a drag `snapTo`s it 1:1 to the finger (raw deltas, never an animated value fed back into the accumulator — that compounded lag and the sheet crept), and on release it springs toward the target while KEEPING the finger's release velocity (`animateTo(..., spring(dampingRatio = CRITICAL /*1.0 — no overshoot*/), initialVelocity = v)` — momentum; the old `animateFloatAsState` restarted the spring from rest on every release = the visible stutter; a slightly-underdamped 0.9 bounced past fullHeight, pushed `fraction` back over the bubble gate and ping-ponged the shared surface sheet↔bubble = black flicker). The collapse is a SLIDE + FADE — the WHOLE sheet Box follows the finger 1:1 via its own `Modifier.offset { IntOffset(0, sheetOffset) }` (a plain LAYOUT offset, NOT `graphicsLayer` — any layered ancestor of the TextureView renders BLACK, a bug that shipped once: "player area just black + black flickering popup"), and as it slides a black veil overlaying the column (`Color.Black.copy(alpha = collapse)`, a plain opaque overlay — it MUST be a sibling Box overlay, NOT a Column child, else a `fillMaxSize` child inside the Column starves the weighted detail to 0px) dims video + detail + controls progressively so the player fades out completely. Only when the sheet is essentially FULLY off-screen (`collapse >= 0.98f`) does the mini bubble OPEN, with its OWN enter animation — scale-in pivoted at the corner it lands in (`TransformOrigin` from `miniBubblePos`) + a short fade ("open the mini player with an animation"); there is deliberately NO continuous morph — the player must be fully hidden BEFORE the mini opens. The draggable is disabled at `COLLAPSED` so the app behind the bubble stays interactive (the overlay must not swallow touches). The bubble BUILDS IN at the corner it will occupy (no glide from the exit point) — the handoff is gated on `collapse >= 0.98f`. The bubble itself is a BIGGER 16:9 `clip(RoundedCornerShape(14.dp))` rendering the LIVE video surface (same TextureView `ComposePlayer`), tap-to-expand, minimal controls ONLY: play/pause top-left + close top-right (translucent circles), NO progress bar; it's free-dragged like a chat bubble and releasing it springs (`Animatable<Offset>` + `Offset.VectorConverter`) to the NEAREST of the 4 screen corners. Bubble size + corner anchors come from one shared `MiniPlayerGeometry.kt` (`computeMiniPlayerGeometry(maxW, maxH, density, bottomInsetPx)` — the bottom corners are raised above the app's bottom nav bar so the mini never covers it, wired from `MainScreen`'s Scaffold padding), controls are deliberately SMALL (32dp translucent circles w/ 8dp margins, ~17dp icons), and the bubble's top-left is HOISTED (`initialPosition`/`onPositionChange` → `miniBubblePos` in the sheet) so it keeps whatever corner the user snapped it to across collapse/expand cycles. The bubble is gated on `sheetValue == COLLAPSED && collapse >= 0.98f` so the shared engine never paints to two ComposePlayer surfaces, and it MUST be a **sibling of the sheet Box inside the `BoxWithConstraints`** (a child of the sheet would inherit the `.offset` translation and get carried off-screen when collapsed — the "player just turns off / mini player never appears" bug).

## Gotchas
- **Player surface MUST be a TextureView** (`PlayerVideoArea` passes `surfaceType = SURFACE_TYPE_TEXTURE_VIEW` to media3's `Player()`): the player lives in a draggable sheet — the WHOLE sheet Box moves via its own `Modifier.offset { IntOffset(0, sheetOffset) }` (layout placement) and it's re-laid-out on fullscreen, and a `SurfaceView` composites in its own window layer that ignores Compose offset/clip/scale — it punches an opaque black rectangle over the whole app (black screen outside the video, nothing visible in fullscreen, loading spinner/controls occluded). **Hard rule: NEVER put the TextureView (or any of its ancestor boxes: sheet box, video box, bubble) inside a `graphicsLayer` with alpha/scale/translation — the video renders BLACK** (that's the "player area just black + black flickering popup" bug from the round that tried a YouTube shrink-morph). `clip`/`shadow`/layout-`offset` are fine (the bubble uses corner clip + shadow and renders the live video; its enter animation lives on the AnimatedVisibility/parent and its drag/snap use a layout `offset` — never a surface ancestor). TextureView renders through the normal hierarchy and tracks the sheet. Same rule in the collapsed `FloatingMiniPlayer` bubble, which also renders the engine via `ComposePlayer` + `SURFACE_TYPE_TEXTURE_VIEW`.
- **Do NOT nest vertical scrollables**: `LazyVerticalGrid` inside an `item {}` of a `LazyColumn` → FATAL "measured with infinity maximum height" (usually triggered by prefetch). The "Related" section of the detail page deliberately uses a non-lazy grid (chunked rows) — keep it that way; any other nested grid must have a bounded height.
- **Player side menus must be OUTSIDE the sheet's Column**: in `VideoPlayerSheet`, the episode/server slide-in `PlayerSideMenu`s live in a sibling `Box` that overlays the whole sheet — NEVER as `Column` children. Their roots are `fillMaxSize()`, so inside the Column they each consume the full Column height and starve every `weight(1f)` child (the detail view, and the video box in fullscreen) down to 0 px — that was the "black below the player" / "everything disappears in fullscreen, progress bar squeezed to the top" bug. Same rule applies anywhere: a `fillMaxSize()` child inside a Column must carry `weight(...)`.
- "Unused" dependencies are **kept as comments** in `app/build.gradle.kts` + `gradle/libs.versions.toml` (datastore-preferences, Firebase, camera, play-services, ...) — don't remove them; uncomment to re-enable.
- `.env`/`.env.example` provide `API_KEY` via the Secrets Gradle Plugin (BuildConfig) for a future Gemini feature — currently just a placeholder, nothing reads it yet.
- Release builds need signing: env `KEYSTORE_PATH`/`STORE_PASSWORD`/`KEY_PASSWORD` or a root `my-upload-key.jks`. Debug needs nothing.
- Configuration cache is on (`gradle.properties`); changing build scripts may trigger a config cache rebuild.
- Versions: AGP 9.3.2, Kotlin 2.4.20, Compose BOM 2026.09.00, media3 1.11.0, Hilt 2.60.1; minSdk 24, targetSdk 36, compileSdk 37.
- **`Element::data()` is CONTENT, not the `data` attribute** (SwiftSoup semantics): on an element it's the accumulated descendant `DataNode`/`Comment` text — i.e. the raw JSON inside `<script id="srcData">` (KKPhim-style sources read their embedded episode/stream JSON straight from it). Both hosts implement it: the test runner's HTML host (collects descendant text/comments) and the app's Jsoup `KrxHostImpl.htmlData` (a direct node handle returns its own content; an element recursively accumulates `DataNode`/`Comment` children). Do NOT "simplify" it back to `attr("data")` — that only reads the HTML attribute, which script-embedded JSON never carries. Covered by `KrxHostImplTest."script element data yields embedded json"` + the Rust runner's `parses_detail_metadata_and_srcdata`.
- **Never `remove(...)` from a jsoup `Elements`, even a copy** (`KrxHostImpl.htmlSiblings`): jsoup's `Elements` overrides `remove(int)` to also call `element.remove()`, which **detaches the element from the source tree** — the whole DOM silently corrupts (sibling/next/parent queries start returning null). `KrxHostImpl.htmlSiblings` builds the sibling list with `parent.children().filterNot { it === node }` (identity filter) instead. Note jsoup's `Element.equals` is content-based, so identity comparison is also the *correct* semantics (never remove a content-equal doppelgänger). Plain `MutableList`/`ArrayList` removal is safe — only `Elements` is dangerous.
- **Don't assume trait methods are the wasm export names — check `macros/mod.rs` `(@single …)` first**: most traits export one function per method (e.g. `DeepLinkHandler.handle_deep_link` → export `handle_deep_link`), but `MigrationHandler` is a **single combined export `handle_key_migration(key_kind: 0|1, anime_key, episode_key)`** — there is NO `handle_anime_migration`/`handle_episode_migration` export. The runner API hides this: `KomoreiRunner.migrate_anime`/`migrate_episode` call `engine.call3("handle_key_migration", kind, desc…, …)` (kind passed as a RAW i32 descriptor, not an encoded pointer); calling the per-method names yields `RunnerException.ExportMissing`. New runner APIs for a trait must be written against the glue's actual exported names (add a runner-side test like `SourceMigrationRepositoryTest.runnerMapsAnimeKeyThroughWasm` to prove it).
- Tests: `app/src/test` runs on JVM with Robolectric (`isIncludeAndroidResources = true`); Roborazzi writes PNG screenshots to `src/test/screenshots/`.
