# AGENTS.md — Komorei

Android anime streaming app, Vietnamese UI. Single `:app` module, package `git.shin.komorei`.
Stack: Compose + Hilt + Room + Media3 (ExoPlayer) + OkHttp/Moshi. No CI, no lint gate.

## Commands
- Fast compile: `./gradlew :app:compileDebugKotlin` (runs KSP — Hilt/Room/Moshi codegen errors surface here)
- Unit tests (JVM, Robolectric + Roborazzi): `./gradlew :app:testDebugUnitTest`
- Single test: `./gradlew :app:testDebugUnitTest --tests "git.shin.komorei.AnimeRepositoryTest"`

## Architecture
- Entry: `MainActivity` + `KomoreiApplication` (Hilt). `KomoreiApplication` exposes an `@Inject dataSourceFactory: KomoreiDataSourceFactory` — composables reach it via `(context.applicationContext as KomoreiApplication)`.
- `di/RepositoryModule`: shared OkHttpClient (User-Agent header, HttpLogging HEADERS, `WebViewCookieJar`, followRedirects) + ImageLoader + Room DB. Cookies from WebView flow into every media request automatically.
- **ALL data is fake** (commit "fake data"): `AnimeRepository` is mocked, `delay()` simulates the network. `getStream` returns real sample URLs (Mux HLS + public sample MP4s) so playback actually works. Retrofit is an unused dependency — scaffold for real sources. OkHttp/Moshi are used for real (Moshi via codegen for Room converters in `KomoreiTypeConverters`).
- **Anime "Lite" vs "full"**: list APIs return Lite; you MUST call `getAnimeUpdate(anime, needsDetails, needsChapters)` before `getStreamList`/`getStream`. `needsChapters=true` fetches episodes only for the current animeId/season (does not pull sibling seasons).
- **Player flow**: `PlayerViewModel` owns the single `ExoPlayer` engine and `PlayerPlaybackState` mirrors it (via `Player.Listener` + a 250ms position poller) — VM is the single source of truth (player, fullAnime, streams, selectedStreamId, streamData, segment interceptors). `AnimeDetailView` is a pass-through view. Flow: `openAnime`/`selectEpisode` → `loadStreams` (getAnimeUpdate needsDetails=true → getStreamList → getStream first server) → `buildMediaSource` on the shared engine.
- **Watch history / auto-resume**: written via `LibraryRepository.saveProgress` — `PlayerViewModel.saveWatchTime()` fires on the poller (~every 5s of playback) + at boundaries (pause, openAnime/selectEpisode switch, STATE_ENDED, dismiss). Resume uses `LibraryRepository.getWatchTime(...)` (a **suspend** seam — later a remote watch history can plug in without changing call sites), called after `buildMediaSource` in `loadStreams`/`selectStream` (not on `retryStreams` refresh) to `seekTo` the saved position; episodes ≥95% watched restart from 0. `dismissPlayer()` fully releases the engine (`stop()` + `clearMediaItems()`) and resets the whole `PlayerPlaybackState` (anime/episode/tracks/ranges/position) so reopening starts clean — a bare `pause()` left the stale source prepared (frozen frame + leftover state).
- **Player UI**: `VideoPlayerSheet` renders the engine inside `PlayerVideoArea` → media3 **`media3-ui-compose-material3`** `Player()` composable (official Compose UI, same 1.11.0 version) with custom top/center/bottom slots in the app's dark theme. Gestures (`PlayerGestures.kt`, ported from the official media3 demo `demos/compose/.../layout/modifiers.kt` — Apache-2.0): single-tap toggles controls, double-tap seeks ±10s (left/right half), hold-right-half fast-forwards 2x (VM remembers/restores base speed), vertical swipe left = window brightness / right = `player.volume`; thin AnimeRed progress line stays at the bottom edge when controls autohide (3.5s). In-player slide-in side menus (`PlayerSideMenu.kt`, like the anime-vsub reference): playlist icon opens the episode/season picker (`EpisodesContent` — shared with the detail `EpisodesBottomSheet`), Dns icon opens the server picker (`ServerMenuContent`), and a SkipNext button jumps to the next episode of the current season/chunk (hidden at the last one). Fake HUDs are gone — Refresh re-resolves the stream, Settings opens a playback-speed menu, Fullscreen drives `PlayerPlaybackState.isFullscreen` + immersive system bars.
- **Media3**: media source = `DefaultMediaSourceFactory(KomoreiDataSourceFactory)` (auto-detects HLS vs MP4). `KomoreiDataSourceFactory.configure(streamData, urlInterceptor?, dataInterceptor?)` injects `streamData.headers` into every sub-request and wraps with `TransformableHttpDataSource` when an interceptor is present.
- **Segment transformer**: `AnimeRepository.segmentUrlInterceptor`/`segmentDataInterceptor` are open/null — a real source just overrides these two properties and gets wrapped automatically.
- `StreamData.isContent == false` → treated as not playable (shows loading/error), no media source built.
- Model: `Episode` plays the role of "chapter" (kept the Episode name). `Episode.episodeNumber` is a **String**.
- Every displayed string is a string resource in `res/values/strings.xml` (~119 strings, Vietnamese) — never hardcode.

## Gotchas
- **Player surface MUST be a TextureView** (`PlayerVideoArea` passes `surfaceType = SURFACE_TYPE_TEXTURE_VIEW` to media3's `Player()`): the player lives in a draggable sheet moved with `Modifier.offset {}` and is re-laid-out on fullscreen, and a `SurfaceView` composites in its own window layer that ignores Compose offset/clip/scale — it punches an opaque black rectangle over the whole app (black screen outside the video, nothing visible in fullscreen, loading spinner/controls occluded). TextureView renders through the normal hierarchy and tracks the sheet.
- **Do NOT nest vertical scrollables**: `LazyVerticalGrid` inside an `item {}` of a `LazyColumn` → FATAL "measured with infinity maximum height" (usually triggered by prefetch). The "Related" section of the detail page deliberately uses a non-lazy grid (chunked rows) — keep it that way; any other nested grid must have a bounded height.
- **Player side menus must be OUTSIDE the sheet's Column**: in `VideoPlayerSheet`, the episode/server slide-in `PlayerSideMenu`s live in a sibling `Box` that overlays the whole sheet — NEVER as `Column` children. Their roots are `fillMaxSize()`, so inside the Column they each consume the full Column height and starve every `weight(1f)` child (the detail view, and the video box in fullscreen) down to 0 px — that was the "black below the player" / "everything disappears in fullscreen, progress bar squeezed to the top" bug. Same rule applies anywhere: a `fillMaxSize()` child inside a Column must carry `weight(...)`.
- "Unused" dependencies are **kept as comments** in `app/build.gradle.kts` + `gradle/libs.versions.toml` (datastore-preferences, Firebase, camera, play-services, ...) — don't remove them; uncomment to re-enable.
- `.env`/`.env.example` provide `API_KEY` via the Secrets Gradle Plugin (BuildConfig) for a future Gemini feature — currently just a placeholder, nothing reads it yet.
- Release builds need signing: env `KEYSTORE_PATH`/`STORE_PASSWORD`/`KEY_PASSWORD` or a root `my-upload-key.jks`. Debug needs nothing.
- Configuration cache is on (`gradle.properties`); changing build scripts may trigger a config cache rebuild.
- Versions: AGP 9.3.2, Kotlin 2.4.20, Compose BOM 2026.09.00, media3 1.11.0, Hilt 2.60.1; minSdk 24, targetSdk 36, compileSdk 37.
- Tests: `app/src/test` runs on JVM with Robolectric (`isIncludeAndroidResources = true`); Roborazzi writes PNG screenshots to `src/test/screenshots/`.
